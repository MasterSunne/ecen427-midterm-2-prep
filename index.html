Ch 1 An Introduction to Device Drivers

Mechanism vs. policy

  • Mechanism = what capabilities are provided. Policy = how those capabilities are used. A driver provides mechanism, not policy.
  • Drivers are "black boxes": they make the hardware respond to a well-defined internal programming interface and hide how the device works.
  • A policy-free driver: supports synchronous and asynchronous operation, can be opened multiple times, exposes the full capabilities of the hardware, and has no layers that "simplify things."
  • Synchronous call blocks until the operation completes. Asynchronous returns right away; the operation may be incomplete or partial.
  • Different drivers can legitimately offer different capabilities for the same device.
Policy (leave out of the driver)Mechanism (fine in the driver)
Only one process may use the deviceReturn raw register value via read()
Which users may access the deviceReport a hardware error with an error code
Reserving an LED as a heartbeatReport whether an interrupt is pending
Debounce for 50 ms, report only one buttonEnable/disable the GPIO interrupt output

The kernel's five roles

  1. Process management: create/destroy processes, IPC, and the scheduler.
  2. Memory management: virtual address space for every process.
  3. Filesystems: structured filesystem on unstructured hardware; "everything is a file."
  4. Device control: device drivers (our focus).
  5. Networking: packets are asynchronous events, so the OS collects and dispatches them; routing lives here.

Loadable modules

Object code not linked into a complete executable, dynamically linked into the running kernel by insmod, removed by rmmod. Device drivers are only one class of module (filesystems, network protocols, etc. are others).

Classes of devices

  • Char: stream of bytes, node in /dev, implements open/close/read/write. Some char devices (frame grabbers, our HDMI framebuffer, /dev/uio0) act like a data area you can lseek()/mmap() in. Seeking does not make it a block device.
  • Block: can host a filesystem. Linux lets apps transfer any number of bytes, so char vs. block differs only in the kernel/driver interface.
  • Network interface (eth0): sends/receives packets, so no /dev node; the kernel calls transmit/receive functions instead of read/write.

Security and licensing

  • Driver code runs in kernel mode: a bad pointer, length or value from a user program can corrupt kernel memory, crash the system, or grant access. The driver is responsible for checking.
  • Linux is GPLv2, a copyleft license: if you distribute the code or a derived work, recipients get source under the same license. Permissive (MIT/BSD/Apache): take it, close it, ship it. Modifying for private use obligates nothing.
  • Modules should declare MODULE_LICENSE("GPL"). Anything else taints the kernel and blocks EXPORT_SYMBOL_GPL functions (Lab 5 needs those). User-space drivers sidestep it: the GPL stops at the system-call boundary.
Exam traps. Mechanism and policy are easy to swap: mechanism is what, policy is how. "Can lseek" doesn't mean block device. "Only one opener" and "permissions" are policy. GPL obligations start at distribution.

Ch 2 Building and Running Modules

#include <linux/init.h>
#include <linux/module.h>
MODULE_LICENSE("GPL");

static int __init hello_init(void) {
    pr_info("Hello, world\n");
    return 0;              /* nonzero = load fails */
}
static void __exit hello_exit(void) {
    pr_info("Goodbye\n");
}
module_init(hello_init);
module_exit(hello_exit);
  • No main(): init registers what the module can do and returns; the kernel calls the other functions later. Every module is event-driven.
  • module_init()/module_exit() name the load/unload functions; the function names don't matter.
  • No module_exit → the module cannot be unloaded.
  • Exit must undo everything init did. A module is not a process, so nothing is cleaned up for it; leaks persist until reboot.

Modules vs. applications

  • Linked only to the kernel: may call only functions the kernel exports. No libc, no printf (use printk/pr_*).
  • No floating point: saving/restoring FPU state on every kernel entry/exit isn't worth it.
  • Tiny kernel stack (4–16 KB, shared with the whole call chain). Overflow silently corrupts memory. Big buffers → kmalloc/vmalloc or static.
  • Reentrant: code runs in several contexts at once (multiple processes, ISRs, preemption, both PYNQ cores). One copy of each global/static is shared by all.
  • Process context (system call): current → struct task_struct of the caller (current->comm, current->pid). Interrupt context: current is meaningless; don't use it.

Build and load

  • Built by the kernel's own build system (make -C /lib/modules/$(uname -r)/build M=$(PWD), obj-m := hello.o).
  • vermagic string baked into the .ko (release, SMP, preempt, arch). Mismatch → "Invalid module format". Rebuild after any kernel update. View with modinfo.
  • insmod, rmmod, lsmod, modprobe (resolves dependencies), dmesg.
  • rmmod says "in use" → a program still has the device open (or another module depends on it).
  • Module stacking: a module uses symbols another exports (EXPORT_SYMBOL / EXPORT_SYMBOL_GPL); insmod resolves against the kernel symbol table.

Error handling with goto

err = register_this(ptr1, "skull"); if (err) goto fail_this;
err = register_that(ptr2, "skull"); if (err) goto fail_that;
err = register_those(ptr3,"skull"); if (err) goto fail_those;
return 0;
fail_those: unregister_that(ptr2, "skull");
fail_that:  unregister_this(ptr1, "skull");
fail_this:  return err;

Labels unwind in reverse order. If step k fails, jump to the label that undoes step k−1, then fall through. If register_that fails, only unregister_this runs.

Ch 3 Char Drivers

Device numbers

  • A device file has no contents: it's a name attached to a major (which driver) and minor (which device that driver manages) number. One driver, four adapters → one major, four minors.
  • ls -l: crw-rw---- ... 188, 1 → char device, major 188, minor 1.
  • dev_t holds both. Use MAJOR(dev), MINOR(dev), MKDEV(ma, mi); never bit-shift by hand.
  • alloc_chrdev_region(&dev, firstminor, count, name): dev is output only; kernel picks the major. register_chrdev_region(first, count, name) if you know the major. Free with unregister_chrdev_region(dev, count).

Registering the cdev (this order)

  1. alloc_chrdev_region()
  2. cdev_init(&cdev, &fops), then cdev.owner = THIS_MODULE
  3. cdev_add(&cdev, devno, count): live immediately. Methods may be called before init/probe finishes, so set up everything they use first.

Remove with cdev_del(). The /dev node: textbook uses mknod from a script; Lab 5 uses class_create + device_create.

How open() reaches your driver

System-call handler → inode's major/minor → registered cdev → its file_operations.open.

file_operations

ssize_t (*read)(struct file *, char __user *,
                size_t, loff_t *);
ssize_t (*write)(struct file *, const char __user *,
                 size_t, loff_t *);
int (*open)(struct inode *, struct file *);
int (*release)(struct inode *, struct file *);
long (*unlocked_ioctl)(struct file *,
                       unsigned int, unsigned long);
  • Kernel calls through the pointer with a fixed prototype; your function must match exactly.
  • NULL method: behavior varies. NULL .write → user's write() returns −1 with EINVAL.
  • struct inode: one per device file (holds i_rdev and i_cdev). struct file: one per open(). Opening twice → 2 files, 1 inode.
  • file->private_data: NULL at open; set it there (often via container_of(inode->i_cdev, ...)) and use it later. f_pos, f_mode are also in struct file.
  • release runs when the last descriptor sharing that struct file is closed.

read / write and user memory

read() returnsMeaning
== countEverything requested
0 < n < countPartial; caller retries (40 of 100 ready → return 40)
0End of file
< 0Error: return -EFAULT; user sees −1, errno=EFAULT

The driver should update *offp itself; the kernel then copies it into filp->f_pos. The kernel does not add n for you.

Never dereference a __user pointer. It may be unmapped or map to something else in kernel mode; the page may be swapped out (a fault there → oops); and a buggy or malicious program could aim it anywhere.

if (copy_to_user(buf, dev->data, n))
    return -EFAULT;     /* returns bytes NOT copied */

copy_to_user/copy_from_user check the pointer and return the number of bytes still to be copied (0 = success). They may sleep.

Exam traps. The copy functions return bytes not copied. Drivers return -EFAULT; they never set errno. cdev_add comes last because the device is live as soon as it returns. Two opens give two struct files but one inode.

Ch 4 Debugging Techniques

  • printk(KERN_ERR "msg\n"): KERN_ERR is a string literal macro; the compiler concatenates adjacent strings, so no comma.
  • Levels, high to low priority: KERN_EMERG, ALERT, CRIT, ERR, WARNING, NOTICE, INFO, DEBUG (0–7). Messages below console_loglevel reach the log but not the console.
  • Don't call printk directly: use pr_err/pr_warn/pr_info/pr_notice, or dev_err(dev, …) etc. when you have a struct device * (adds the device name).
  • pr_debug()/dev_dbg() compile out unless DEBUG is defined (ccflags-y += -DDEBUG or #define DEBUG before includes).
  • Log buffer: fixed-size circular buffer (CONFIG_LOG_BUF_SHIFT, ~4 KB–32 MB); when full, newest overwrite oldest. dmesg prints without emptying; printk never blocks.
  • Rate limiting: complain once → pr_warn_once(). Occasional repeat while a condition lasts → pr_info_ratelimited() (old: if (printk_ratelimit())). Printing every interrupt at 1 kHz can freeze a slow serial console.
  • Pointer formats: %p prints a hash (since 4.15, to avoid leaking addresses); %px raw address; %pa a phys_addr_t (pass a pointer to it); %pR a struct resource; %pS a symbol name such as my_isr+0x14/0x40.
  • Oops: usually a NULL/bad pointer dereference. PC is at audio_write+0x4c/0x120 [audio] → faulting instruction is 0x4c bytes into a 0x120-byte function in module audio. "NULL pointer dereference at virtual address 00000010" → accessing a field at offset 0x10 of a NULL struct pointer.
  • Other tools (textbook): /proc and sysfs files, strace (watch system calls from user space), gdb on /proc/kcore, kgdb.
Exam traps. _once stops after the first message; _ratelimited keeps printing occasionally. A %p value that looks wrong is just hashed, not a failed mapping.

Ch 9 Communicating with Hardware

I/O registers vs. RAM

  • I/O operations have side effects (writing Reset clears Config; reading a status register may clear it). RAM accesses don't.
  • For speed, RAM accesses get cached (by compiler in CPU registers, by hardware caches) and reordered (by compiler and by CPU). Fine for RAM, fatal for I/O.
  • Hardware caching: already disabled for I/O regions by the platform setup.
  • volatile stops the compiler from caching/reordering accesses, but the CPU can still reorder → need memory barriers or the I/O accessors.
  • Barriers: barrier() (compiler only), rmb() (reads), wmb() (writes), mb() (both); smp_* variants for SMP only.

Example from lecture

p[0] = 2;   /* Config */
p[1] = 1;   /* Reset: clears Config */
printk("%d\n", p[0]);   /* expect 0 */

Without protection the compiler may keep p[0] in a register and print 2, or the stores may be reordered so Reset happens first.

Claiming and mapping I/O memory

struct resource *r;
r = request_mem_region(phys, size, "audio");
if (!r) return -EBUSY;
base = ioremap(phys, size);   /* virtual addr */
if (!base) { release_mem_region(phys, size);
             return -ENOMEM; }
v = ioread32(base + OFFSET);  /* void __iomem* */
iowrite32(v, base + OFFSET);
/* teardown, reverse order */
iounmap(base);
release_mem_region(phys, size);
  • request_mem_region: reserves a physical range so other drivers can't claim it. Makes no mapping. Visible in /proc/iomem.
  • ioremap: page tables map the physical range to a kernel virtual address. Don't dereference it; use ioread8/16/32, iowrite8/16/32 (portable, ordered relative to each other).
  • Pointer arithmetic scales by type: with u32 *regs, byte offset 8 is regs + 2. With void __iomem *base (or u8*), it's base + 8.
  • I/O ports (x86): request_region, inb/outb; ARM uses memory-mapped I/O only.
Exam traps. request_mem_region doesn't map anything; ioremap maps but doesn't reserve. volatile alone isn't enough. Count offsets in bytes vs. elements. Undo in reverse order.

Ch 10 Interrupt Handling

irqreturn_t my_isr(int irq, void *dev_id) {
    struct my_dev *d = dev_id;
    u32 s = ioread32(d->base + STATUS);
    if (!(s & MY_IRQ_BIT))
        return IRQ_NONE;      /* not ours */
    iowrite32(MY_IRQ_BIT, d->base + STATUS); /* ack */
    return IRQ_HANDLED;
}
err = request_irq(irq, my_isr, 0, "my_dev", d);
...
free_irq(irq, d);   /* same dev_id */
  • Pass the function name (my_isr), not a call. Prototype must be irqreturn_t f(int, void *).
  • dev_id is whatever pointer you gave request_irq; usually your device struct, so one handler can serve several devices.
  • Return IRQ_HANDLED if your device interrupted, IRQ_NONE if not (required for shared lines, flag IRQF_SHARED; old name SA_SHIRQ).

Rules for handlers (interrupt context)

  • No process: no current, no user address space → no copy_to/from_user.
  • Cannot sleep: no mutex_lock, msleep, wait_event, kmalloc(GFP_KERNEL) (use GFP_ATOMIC).
  • OK: ioread32/iowrite32, driver globals, spin_lock, ratelimited prints.
  • Interrupts disabled on this CPU while it runs: keep it short.
  • Acknowledge the device (or disable its interrupt output) before returning. A level-triggered line still asserted fires again immediately → system appears to hang.
  • Ordering: request_irq before telling the device to interrupt; free_irq after telling it to stop. Set up everything the ISR uses (buffers, locks, mapping) before request_irq.
  • /proc/interrupts: per-CPU count per line plus the registered name. /proc/stat: totals.
  • Top half (the registered handler) vs. bottom half (tasklet or workqueue scheduled for later, interrupts enabled). Workqueues may sleep; tasklets may not.
  • disable_irq() waits for running handlers to finish; disable_irq_nosync() doesn't.
Exam traps. request_irq goes before you enable the device's interrupt. A handler that doesn't ack a level-triggered device loops forever. copy_from_user and GFP_KERNEL are not allowed in an ISR.

Lecture 15 Platform Devices and the Device Tree

  • USB/PCI devices announce themselves when the bus is scanned. Memory-mapped SoC/FPGA peripherals can't be asked: these are platform devices and must be described ahead of time.
  • Device tree: data file describing the hardware, separate from the kernel binary. .dts/.dtsi source → dtc → .dtb/.dtbo binary.
  • pynq.dts: base tree loaded by the bootloader (never changed). ecen427.dtsi → ecen427.dtbo: an overlay loaded at runtime with the bitstream (configfs). New peripheral → add a node to the overlay, compile with dtc, load with the bitstream.
ecen427_user_intc {
    compatible = "generic-uio";
    reg = <0x41800000 0x10000>;    /* phys base, size */
    interrupt-parent = <&intc>;    /* the ARM GIC */
    interrupts = <0x0 0x1E 0x04>; /* SPI, #30, level-high */
};
  • compatible ("vendor,device") decides which driver binds. Must match the driver's of_match_table exactly; if not, init runs but probe never does.
  • reg: physical base and size, same as Vivado's Address Editor. Still must be reserved and ioremap'd.
  • interrupts: GIC numbers. Pass platform_get_irq()'s result to request_irq, which is a Linux virtual IRQ number, not 0x1E.
static const struct of_device_id my_of_match[] = {
    { .compatible = "byu,ecen427-audio_codec" },
    { }   /* sentinel */
};
MODULE_DEVICE_TABLE(of, my_of_match);
static struct platform_driver my_driver = {
    .driver = { .name = "audio_codec",
                .of_match_table = my_of_match },
    .probe  = my_probe,
    .remove = my_remove,
};
/* in probe(struct platform_device *pdev) */
res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
irq = platform_get_irq(pdev, 0);
/* /dev file */
cls = class_create("audio_codec");          /* 6.4+ */
dev = device_create(cls, NULL, devno, NULL,
                    "audio_codec");
if (IS_ERR(dev)) return PTR_ERR(dev);

Ch 11 Data Types in the Kernel

  • Three classes: standard C types (int, long), explicitly sized (u8 u16 u32 u64, s8…s64), and types for specific kernel objects (pid_t, size_t, dev_t).
  • Use explicitly sized types when the layout must match something binary: device registers, on-disk/network formats, structs shared with user space (use __u32 etc. in headers user space sees).
  • int/long sizes vary with the architecture (long = pointer size in Linux). Fine for counters and loop indices.
  • Printing _t types: cast to the largest type and use its format: pr_info("%lu", (unsigned long)sz). (%zu also works for size_t.)
  • phys_addr_t is an unsigned integer, not a pointer, so it can't be dereferenced by mistake; physical memory is treated like a huge array indexed by address.
  • Error pointers (<linux/err.h>): some functions (class_create, device_create) return an errno encoded in the pointer, not NULL. 
    if (IS_ERR(p)) return PTR_ERR(p);   /* ERR_PTR(-E) builds one */
    Others (ioremap, kmalloc, request_mem_region) return NULL on failure. Check the documentation for which.
  • Textbook extras: endianness (cpu_to_le32, be32_to_cpu), alignment (get_unaligned), page size (PAGE_SIZE, don't assume 4 KB), struct padding.
Exam traps. Use u32 when matching a register layout, not for loop counters. Checking an error pointer against NULL never catches the error.

Ch 6 ioctl (only this part of Ch 6)

long (*unlocked_ioctl)(struct file *filp,
                       unsigned int cmd, unsigned long arg);
/* shared header, e.g. kernel/audio_codec/audio_ioctl.h */
#define AUDIO_MAGIC 'a'
#define AUDIO_LOOP_ON   _IO(AUDIO_MAGIC, 0)
#define AUDIO_LOOP_OFF  _IO(AUDIO_MAGIC, 1)
#define DEV_IOC_GET_TEMP _IOR(DEV_MAGIC, 3, __u32)
#define DEV_IOC_SET_RATE _IOW(DEV_MAGIC, 4, __u32)

switch (cmd) {
case DEV_IOC_GET_TEMP:
    return put_user(read_temp(), (u32 __user *)arg);
case DEV_IOC_SET_RATE:
    return get_user(rate, (u32 __user *)arg);
default:
    return -ENOTTY;   /* unknown command */
}
  • Command number fields: type (magic, 8 bits), number (ordinal, 8 bits), direction, size of the argument. Check Documentation/ioctl-number for magic numbers.
  • Why the macros: numbers unique system-wide, so a command sent to the wrong device isn't obeyed (returns -ENOTTY).
  • Direction is from the application's view: _IOR = app reads → driver writes to user memory (put_user/copy_to_user). _IOW = app writes → driver reads (get_user/copy_from_user). _IOWR both; _IO no data.
  • arg is an integer or an unchecked user pointer. Never dereference it. For a large struct, the program passes a pointer, driver uses copy_to_user.
  • access_ok() checks a range is user space (most code skips it: copy functions check). __put_user/__get_user skip the check.
  • Why disliked: every command is effectively an undocumented system call, can't be audited, untyped argument is hard to make portable.
  • Use .unlocked_ioctl (the old .ioctl held the big kernel lock and no longer exists).
Exam traps. _IOR means the driver writes to the user. Unknown command returns -ENOTTY. *(u32*)arg = x is always a bug.

Ch 5 Concurrency and Race Conditions

Vocabulary

  • Race condition: result depends on how threads happen to interleave.
  • Critical section: code touching shared state that must not overlap with other code touching it.
  • Atomic: one indivisible step. "Check, then take" is not atomic.
  • Deadlock: everyone holds one lock and waits for another. Fix: a global lock order (lower-numbered fork first).

Dining philosophers: two neighbors both see a fork FREE before either stores its id. A per-fork mutex makes check-and-take atomic; it's released before eating; different forks can be taken in parallel. Passing on one core (taskset -c 0) proves nothing: the race window is just rarely hit.

Why the kernel is worse

Driver code can run concurrently with itself from: multiple processes, multiple threads sharing an fd, SMP (PYNQ has two Cortex-A9 cores), kernel preemption, and interrupts.

Needs a lock: globals/device-struct fields touched by more than one context (buffers, index+length pairs, totals). Doesn't: locals, function arguments, const tables.

LDD3 ground rules: avoid shared state; lock what you share; don't make an object visible to the kernel (cdev_add, request_irq) until it's fully set up, including spin_lock_init.

MutexSpinlock
Waitersleepsspins (busy-waits)
Use in ISR?noyes
Sleep while held?yesnever
APImutex_init/lock/unlockspin_lock_init/lock/unlock

LDD3 uses struct semaphore; modern kernels use struct mutex.

Never while holding a spinlock: copy_to/from_user, kmalloc(GFP_KERNEL), mutex_lock, msleep. iowrite32 and reading struct fields are fine. Holding a spinlock disables preemption, not interrupts.

Spinlocks + interrupts

write() on CPU 0 holds the lock with plain spin_lock; the device interrupts CPU 0; the ISR spins on a lock its own CPU holds → deadlock. Fix:

unsigned long flags;               /* in write/read/ioctl */
spin_lock_irqsave(&lock, flags);  /* local IRQs off */
...
spin_unlock_irqrestore(&lock, flags);
spin_lock(&lock);                  /* in the ISR */

If the ISR fires on the other CPU it just spins briefly. Lock ordering: take the mutex first, spinlock second (taking a mutex under a spinlock could sleep).

Exam traps. mutex in ISR = bug (may sleep). plain spin_lock outside the ISR = occasional freeze. Disabling a device's interrupt doesn't wait for an ISR already running on the other core.

Lab 5 Audio Driver

Hardware

  • ADAU1761 codec, configured over I2C from user space (audio_config_init()); samples go out over I2S.
  • Two TX FIFOs (left, right), 1024 entries each, drained at 48 kHz (one sample every 20.83 µs). Full FIFO lasts 1024/48000 ≈ 21.3 ms, too short to refill from user space, hence a kernel driver with an ISR.
  • With INT_EN = 1, interrupt when a FIFO is ≥75% empty (≤256 entries left: ≈5.3 ms of audio).
  • 24-bit samples in the low bits of a 32-bit register. Status register: TX_DATACOUNT_L (bits 20–11), TX_DATACOUNT_R (10–1), INT_EN (bit 0).
  • WAV files: mono, 16-bit signed LE, 48 kHz, 44-byte header. User space converts each 16-bit sample to 24-bit in a 32-bit int (shift left 8). Longest clip ≈ 63,676 samples (1.33 s).

Milestone 1: skeleton

  • init: alloc_chrdev_region, class_create, platform_driver_register.
  • probe (compatible "byu,ecen427-audio_codec"): cdev_init/cdev_add, device_create named audio_codec (udev rule → /dev/ecen427/audio_codec, no sudo), platform_get_resource, request_mem_region, ioremap, platform_get_irq, request_irq, then enable the core's interrupt output.
  • Goto-based rollback; check IS_ERR on pointer-encoded returns.
  • Grading: load/unload twice, run audio_driver_test1, check the log.

Milestone 2: playback

  • write(): stop/disable interrupts → check count fits → copy_from_user → reset index, sample count (count/4), playing flag → enable interrupts → return count. A new clip replaces the current one.
  • ISR: if samples remain, push to both L and R FIFOs (up to free space / 75% full), watch the end of the clip, disable interrupts at the end.
  • read(): copy 1 byte (0/1 = is playing) with copy_to_user; always return 1.
  • Sample buffer is large (lab suggests 512×1024 u32 = 2 MB): put it in the static device struct, never on the stack.
  • audio_driver_test2: config init, open, write clip, poll read() until 0, write again. No sleep().
  • #1 bug: samples vs. bytes. count and copy_from_user are bytes; indices and FIFO counts are samples (bytes/4).

Milestone 3: ioctl + Space Invaders

  • .unlocked_ioctl with two _IO commands: enable / disable looping (header in kernel/audio_codec/).
  • Priority: UFO highest (looped, blocks others), walk1–4 lowest (only when idle), everything else medium.
  • Load WAVs once at startup; path from argv[1]. Zero warnings.

Locking (lecture fix)

Mutex write_lock: one write() at a time, protects sound_file (copy_from_user may sleep). Spinlock lock: num_samples, current_idx, is_playing, is_looping, shared with the ISR. ISR uses spin_lock (every return → goto out); write/read/ioctl use spin_lock_irqsave. read(): copy is_playing to a local under the lock, copy_to_user after unlocking. Init both locks in probe before cdev_add and request_irq.

Exam traps. write() returns bytes (count), not samples. disable_intr() doesn't wait for an ISR running on the other core. Fill both channels. read() returns 1, not the flag value.
